# 安全设施设计报告工作台

本轮优化增加项目进度导航、可停止的生成前资料检查、资料来源登记，以及限定场景的消防用水量和厂房泄压面积辅助计算。计算结果先保存为待复核，使用前须核验输入、规则版本与适用条件。功能范围、公式边界和未完成验收项目见 [本轮优化与一期范围核对](docs/本轮优化与一期范围核对.md)；历史版本说明保留用于追溯。

v0.9.0 接入 LangGraph 章节 Agent 图：资料规划 Agent 生成检索问题，受限工具在本项目证据库中补充检索，撰写 Agent 生成章节，质量审核 Agent 按结构、来源和可读性检查结果决定是否进行一次定向返修。每章在界面显示可审阅的角色与动作记录；不启用 LangSmith，也不发送项目资料用于追踪。模型调用次数和成本会比单次直写增加。

v0.8.0 增加专业分析/计算复核台账、一期质量检查和 GB 18218-2018 重大危险源辨识指标计算；其余专业计算记录输入来源、规则版本、公式/过程、结果和复核人，只有经专业人员核验的记录进入章节证据。见 [一期范围实现与验收矩阵](docs/一期范围实现与验收矩阵.md)。该版本仍是本地验证原型；消防水量、泄压面积、防火间距等公式、法规自动更新和真实项目准确率验收需经公司专业人员核验后实施。

v0.6.0 在点击生成后自动按本次章节范围预检资料缺口；发现缺项时先弹出交互补充窗口，答复只作为对应章节的待核实证据传入，也可暂时跳过。支持首次生成前检查。另支持本章资料需求诊断、章节专属自然语言提示词、显式选择重写章节，以及在报告中增删自定义章节。v0.4.0 起支持新项目从单章开始生成，并在 Word 中把未生成或失败章节明确标为待完成。语义检索与中文关键词检索采用 RRF 融合召回；每个项目独立保存索引，章节技能通过开放的 `SKILL.md` 目录加载。

日常使用请双击 [操作手册.html](操作手册.html)，或阅读 [操作手册.md](操作手册.md)。手册可离线打开、打印，当前更新日期为2026年11月26日；外观现有七套主题。维护手册时编辑 `操作手册.md`，安装开发依赖后运行 `python tools/build_manual.py` 同步生成HTML；运行 `python tools/build_manual.py --check` 检查两份是否一致。

桌面版打包入口为 `tools/build_desktop.py`；平台条件和数据迁移步骤见 [桌面版安装与迁移说明](docs/交付与验收/桌面版安装与迁移说明.md)。

本机已构建并启动检查的 macOS ARM64 桌面试制包：[`安全设施设计报告工作台-v0.9.0-macOS-arm64.zip`](dist/安全设施设计报告工作台-v0.9.0-macOS-arm64.zip)，校验文件：[SHA-256](dist/安全设施设计报告工作台-v0.9.0-macOS-arm64.zip.sha256)。这是未签名/未公证的内部验证包。Windows、Linux 需在对应原生系统构建并通过目标环境验收后交付。

标准实施、数据确认、测试记录和交付模板见 [交付与验收目录](docs/交付与验收/项目实施与验收控制.md)、[测试计划](docs/交付与验收/测试计划与记录.md)、[交付清单](docs/交付与验收/软件交付物清单.md) 和 [技术说明](docs/交付与验收/技术说明.md)。安装包平台与甲方样本、验收阈值仍需双方确认。

## Windows 独立运行

Windows 10/11 首次使用时，先安装 Python 3.13，再双击根目录的 `初始化Windows环境.cmd`。当前 Windows 开发机优先使用 `E:\download\Python313\python.exe`，其他电脑可通过 Python Launcher 提供 `py -3.13`。初始化程序会在项目目录创建独立的 `.venv` 环境，安装 `requirements-dev.txt` 中记录的运行与测试依赖，并执行基础导入检查。该环境和依赖不会提交到 Git 仓库，也不会修改 Mac 的运行环境。

初始化成功后，双击 `启动工作台-Windows.cmd`。启动入口在后台运行本项目的 Python 服务，等待页面就绪后打开 `http://127.0.0.1:8765`，运行日志保存在 `data/logs/windows-workbench.log`。使用结束并确认任务已完成后，双击 `停止工作台-Windows.cmd`；停止入口只结束本项目记录的进程，不会批量结束电脑上的其他 Python 程序。

开发者也可以在 PowerShell 中执行：

```powershell
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m safety_report
```

若需要构建 Windows 桌面包，再安装 `requirements-desktop.txt` 并执行 `tools/build_desktop.py`。桌面包必须在 Windows 原生环境构建和验证。

## Mac 独立运行

双击根目录的 `启动工作台.command`。页面地址为 `http://127.0.0.1:8765`。服务由 macOS 用户后台任务管理，关闭终端、浏览器或聊天不会停止；退出登录、关机或重启后需再次双击启动。等待任务结束后，可双击 `停止工作台.command` 停止。

生成过程中可在页面进度栏点击“停止生成”。取消会关闭正在进行的流式模型请求，不创建不完整的新版本，原草稿保留。若所选模型服务不支持流式响应，当前请求可能要等响应结束后才停止。

启动入口优先使用项目 `.venv/bin/python`，不存在时才使用 PATH 中的 Python 3。当前这台电脑已经安装项目依赖。新电脑第一次安装时，由管理员执行：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

中文语义检索使用 Qdrant 本地持久化模式和 `BAAI/bge-small-zh-v1.5` FastEmbed 模型。第一次分析项目资料时会从模型仓库下载模型，之后索引保存在该项目 `data/<项目ID>/knowledge/qdrant/` 下。首次下载需要网络；离线环境需预先缓存模型文件。用户资料和向量索引留在本机项目目录，生成报告时仍只向页面所配置的大模型服务发送检索到的章节证据。

运行代码最低需要 Python 3.11；协同开发环境和 GitHub Actions 统一使用 Python 3.13。模型在页面“模型设置”中配置并保存到 `data/settings.json`，密钥不经 GET 接口回传，文件权限设为 0600。换供应商或服务地址时，不复用旧地址的密钥。开发启动也可使用 `python3 -m safety_report`；Windows 使用 `.\.venv\Scripts\python.exe -m safety_report`。

`tools/run_workbench.py` 会读取根目录 `.env` 中允许的设置项，不执行 shell 插值。网页选择的模型配置按任务快照传入，不通过修改进程环境切换模型。原环境变量配置仍可作为“管理员环境配置”使用。

## 报告工作流程

1. 保存一个可用模型配置：服务地址、供应商 Key 和模型 ID。支持手动获取列表和不含项目资料的连接测试。
2. 新建或进入已有项目。上传新增文件，选择“事实资料 / 参考样例 / 图件 / 仅归档”等用途。
3. 读取资料，复用既有解析结果，保留手工信息；冲突候选需重新核对。
4. 确认基本信息。已填写但未确认的字段会阻止生成并在页面提示，不再静默忽略。
5. 上传或选择已有图件，设置图题、PDF 页码、是否放入报告。
6. 新项目建议选择“只生成或重写所选章节”，先写一章，核对事实、分析、缺项和表达后再逐章继续。已有报告默认按章选择；在编辑区可以让模型列出本章缺少的材料、写自然语言修改要求后重写，也可增删自定义章节。需要时补充资料后只重写相关章节，无需从头上传。模型结合证据与原章节归纳改写；未选章节不变。
7. 在页面修改正文、补充段落、修改表格或新增表格行，保存为新版本。
8. 导出干净正文 Word 与独立核对清单；从版本记录可下载旧稿或恢复为新版本。

无模型时只能明确选择“编写提纲”，不调用模型，也不把长段资料原文拼贴成完整报告。智能编写会要求模型记录采用、略去、待核对的资料主题，并要求正文引用已采用的证据；如果兼容模型没有返回编辑记录，工作台会从正文的证据引用生成“已引用 / 未直接引用”清单，不会仅因返回格式阻止报告保存。同时检查“资料摘录”、表格粘贴和与引用原文过度相似的段落，发现问题时会要求模型重写一次。仍未通过时，新版本不会保存，上一版保留。旧版报告会标记“待重新编写”。这些规则可挡住明显的复制堆积，但仍需专业人员审阅事实、逻辑和技术结论。

## 文件和图件

- DOCX、PDF、CSV、TXT、Markdown、JSON 可以解析。参考报告不纳入本项目事实提取。
- PNG、JPEG、WEBP、BMP、TIFF 可预览和转换为 Word PNG。PDF 图纸可选页渲染，每文件最多 20 页。
- DWG/DXF/SVG 及部分旧办公文件支持归档和原文件下载，当前不直接解释 CAD 内容；请从原软件导出 PDF/PNG/JPG 再嵌入。
- DWL/DWL2、CAD 备份、Office 临时文件自动跳过，不阻断批量导入。DWL/DWL2 不是图纸正文。
- 单文件 80 MB；单项目 100 文件、总计 600 MB。内容相同且用途相同的文件不重复接收。
- PDF 页没有足够的嵌入文字时，自动使用本地 RapidOCR 尝试提取。结果保留原页码，须对照原件核对，尤其是名称、数字和图纸表格。已导入的扫描件可以直接重新读取。

当前参考报告结构配置包含 7 个主章节、105 个一至三级标题、26 张表格的结构和图题信息。它不代表系统能从缺失资料中补齐全部表格或已经复刻所有版式。Word 会隐藏无内容的小节，将证据、缺项和审阅说明放到独立 `review.html` / JSON 中；最终版式和工程内容仍需审核。

## 增量修改和版本

上传、核对、图件变更只标记草稿需要更新，不删除已有报告。解析按文件哈希复用。原手工值优先保留，新增冲突则解除相关确认并提示核对。

报告生成、手工编辑和历史恢复都会写入 `data/<项目ID>/versions/<版本ID>/`，保存当时的 Word、内容、核对清单和元数据。旧版 v0.1 报告在升级时保留成一个历史版本。未生成章节会在 Word 里标出待完成；生成失败或未通过检查的章节不会导出旧版正文，页面仍可查看旧稿并单独重试。支持从第一版起只生成选定章节。保存携带基础版本号，拒绝过期页面覆盖新版本。

Word 中已生成的旧稿不会被新附件或文件变更动态篡改。历史恢复只恢复报告内容，不删除后来上传的资料。当前单实例文件持久化适合小范围验证，正式多用户部署还需企业账户、项目授权、审计和持久化任务队列。

## 公司部署与迁移

推荐由管理员部署到内网服务器，员工只通过浏览器使用公司地址。公司部署不依赖开发者电脑。

```sh
cp .env.example .env
# 设置 APP_PASSWORD；可在页面保存模型，地图功能需 AMAP_WEB_KEY
# HTTPS 反向代理入口将 COOKIE_SECURE 设置为 1
docker compose up -d --build
```

Docker 包含文本 PDF 解析、图片处理、PDF 图件渲染和中文字体。Compose 默认把主机端口绑定在 `127.0.0.1:8765`，需由管理员配置反向代理、公司入口和 HTTPS；上传体积至少允许 80 MB。容器配置已经提供，本机没有 Docker，尚未执行镜像构建验收。

Docker 数据位于 Compose 的 `report-data` 持久化卷，开发数据在根目录 `data/`。迁移不能只复制源码而遗漏数据。

1. 暂停项目组操作，等待任务结束，执行 `sh tools/backup.sh` 导出卷数据。
2. 另行备份源码和 `.env`；模型密钥随数据备份，应妥善保管。
3. 新服务器恢复源码、配置并启动空实例；执行 `sh tools/restore.sh 备份文件路径` 恢复数据。
4. 核查项目、版本、附件、模型连接后再切换公司入口。Mac 本地迁移先停止服务，再备份整个项目。

## 配置与接口

模型使用 Chat Completions 兼容协议：`POST {base_url}/chat/completions`，可调用 `GET {base_url}/models` 获取可用模型。有些供应商没有兼容列表接口，需手动输入模型 ID。模型 ID 从供应商实时查询或控制台填写，避免绑定已下线名称。

内置服务商地址包括 DeepSeek、百炼北京共享地址、Ollama 本机地址与自定义。百炼可以改为自己的工作空间专用地址。远程地址要求 HTTPS；本机服务允许 HTTP。模型重定向会被拒绝，避免把凭据自动转发到其他地址。密钥不记录在请求日志中，不写到浏览器存储。

| 环境项 | 用途 |
| --- | --- |
| APP_PASSWORD | 原型工作台共享访问密码；对外绑定必须配置 |
| LLM_BASE_URL / LLM_MODEL / LLM_API_KEY | 可选的管理员模型配置，网页配置可独立使用 |
| LLM_JSON_MODE | 环境配置的 JSON 输出支持，默认 1 |
| AMAP_WEB_KEY | 地理编码和静态地图服务密钥 |
| COOKIE_SECURE | HTTPS 入口设 1，本地 HTTP 设 0 |
| DATA_DIR | 持久化数据目录 |
| CJK_FONT | 流程图 PNG 中文字体路径 |

协议参考：[DeepSeek 模型列表](https://api-docs.deepseek.com/api/list-models/)、[百炼服务地址](https://help.aliyun.com/en/model-studio/base-url)、[Ollama 兼容接口](https://docs.ollama.com/api/openai-compatibility)、[PDFium 线程约束](https://pypdfium2.readthedocs.io/en/stable/python_api.html)、[Autodesk 临时文件说明](https://www.autodesk.com/support/technical/article/caas/sfdcarticles/sfdcarticles/DWL-and-DWL2-files-are-created-while-working-on-AutoCAD.html)。
