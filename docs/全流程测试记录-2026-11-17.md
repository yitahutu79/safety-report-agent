## 2026-11-18 生成卡顿原因排查与整改

- 证据：Ollama 日志 19:57:21 内存峰值 6.64 GiB；机器物理内存 8 GiB。排查时模型已卸载，系统交换空间仍占用 9327.94 MiB，不能全部归因于模型。
- 流程缺陷：原小节最多合并 3 标题、8 条各最多 1200 字证据，沿用 8000 token 输出额度；单组或无 checkpoint 时回退整章；网络读取超时不等于总执行时限。
- 整改：本机 Ollama 每次一个标题、最多 3 条证据、2000 token 输出；其他服务小节输出 4000 token；单小节同样走拆分流程；无 checkpoint 仍拆分但不持久化。已完成小节继续校验和落盘，升级写作缓存键避免复用旧策略节点。
- 筛选：复用现有 GPT Researcher 适配器，本地模型按 3 条一批，不省略筛选记录。
- 传输：流式响应即使没有 cancel_event 也正确解析；增加总时限 watchdog（默认 240 秒，包括已建立连接后的流式读取），到期关闭连接；小节总时限失败不立即原样重试。建立连接阶段仍受 socket timeout 约束。
- 自动测试：138 项通过，新增真实 HTTP 慢速流验证总时限，以及单标题本地写作预算测试。测试中的传输替身不作为真实报告质量验收。
- 真实资料受限实测：综合分析转换稿 body[3] 建设单位名称，仅发送该片段至本机 qwen3.5:4b；13.92 秒返回正确 JSON，finish_reason=stop，未输出推理。结果保存在 /private/tmp/safety-real-probe.json，未创建正式报告版本。测试后卸载模型。
- 未通过的验收项：完整真实章节/报告质量尚未验证；原始 DOC 转换丢表格、SDS 扫描页缺 OCR 仍需处理；整章审稿及预检仍需继续做上下文预算治理。本轮不宣称这些问题已解决。
