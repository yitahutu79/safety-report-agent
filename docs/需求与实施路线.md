# 安全设施设计报告智能体需求与实施路线

本文件记录最初的需求与分阶段计划；实现状态请以 [一期范围实现与验收矩阵](一期范围实现与验收矩阵.md) 为准。当前本地原型版本为 v0.7.0。本文对生产化和未实现能力的历史规划仍有参考价值。

本项目为公司建立可迁移、可部署、具有操作界面的报告生产工具，目标是根据各项目原始材料生成结构一致、来源可追溯、可以继续编辑的安全设施设计 Word 报告。使用者通过浏览器操作，管理员负责部署，工程人员负责核对资料和技术结论。

## 参考报告拆解

参考文件为用户指定的《正文+附件.docx》，原文件只读，未修改。程序基于 OOXML 结构识别出 7 个主章节、105 个一至三级标题、26 个正文表格、85 个内嵌媒体资源和 9 个分节。没有将缓存页数作为实测页数。完整结构见 `reference/profile.json`。

| 章节 | 主要输入 | 主要输出 |
| --- | --- | --- |
| 设计依据 | 备案、批复、合同、设计范围、经核验的标准库 | 文件清单、适用规范、设计依据 |
| 建设项目概况 | 企业资料、项目说明、工艺、物料清单、设备表、总图、公用工程 | 企业和产品表、物料表、设备表、位置图、工艺图 |
| 危险源及有害因素 | SDS、储存单元、最大在线量和储量、工艺与设备条件 | 物料危险性、危险因素、辨识过程及待审核结论 |
| 安全建议采纳情况 | 安全生产条件和设施综合分析报告、设计落实说明 | 建议与采纳情况逐条对照表 |
| 安全设施设计防范措施 | 总图、建筑、工艺、电气、消防设计资料和参数 | 各专业措施、设施清单、投资概算 |
| 结论和建议 | 各章核实结果、缺项、符合性与设计审核记录 | 受证据支持的结论与建议 |
| 附件 | 营业执照、备案文件、SDS、已审图件等 | 有编号的附件清单和图件汇编 |

样例表格包括企业信息、产品产量、建设内容、物料储存、消防用水、主要设备、特种设备、周边关系、危险化学品特性、危险因素、重大危险源辨识、建议采纳、防爆与报警、劳动防护、安全标志、投资概算和安全设施清单等。正式版本应逐表规定字段、单位、校验规则和来源，不依赖模型自由决定表格结构。

## 系统形态

员工浏览器连接公司服务器。后端负责文件读取、OCR/图纸适配、证据索引、信息提取、任务调度、章节生成、计算与校验、排版与导出。模型和地图通过服务器适配器调用，可更换供应商。上传文件、事实、审核记录与导出版本应持久化。

原型采用 Python 服务、无构建前端和文件目录持久化，降低开发演示门槛。正式多用户版本应迁移为成熟 Web 框架、数据库、对象存储及持久化任务队列，配合企业认证和项目级授权。当前共享密码仅是原型入口控制，不等于账户系统。

## 信息与证据

事实应同时保存值、单位、建设阶段、对象、来源文件哈希、页码/段落/表格位置、提取方式、置信标记和审核状态。同一公司的一期、二期、全厂、项目范围数据必须分开。不同来源存在冲突时，使用者选择并记录理由，不自动覆盖。

业务实体至少包括项目、企业、产品、物料与 SDS、储存单元、建筑、设备、公用工程、周边目标、安全设施、规范依据和附件。原型目前只提供 7 个基本字段的候选提取；其它实体是正式开发范围。

新上传资料使已生成报告失效，避免旧报告显示为最新结果。每个项目目录相互独立，但原型未实现不同用户的项目访问权限。正式版需增加版本号、修改者、修改时间和不可变的证据快照。

## 计算和专业校核

消防水量、设施投资、容量汇总、单位换算及危险源比值等应交由经测试的确定性计算工具。模型可以解释工具结果，不能自行补齐临界量、设计参数或标准条款。所有规则必须记录规范来源、版本、适用条件和校核日期。原型没有实现这些工程规则，因此不应把其草稿当作专业判断。

规范库必须分别管理原文来源、发布日期、实施日期、替代关系、地域与行业适用性。样例中的规范名称和年份仅是未核验的历史引用；当前未对其现行有效性作判断。正式项目需核验后才能成为自动编写依据。

地图采用地址查询、候选确认、静态图获取的流程，保存经纬度、坐标系、供应商、缩放级别和采集时间。位置图用于展示区位；周边关系、厂界、间距和防护距离应来自经核验的图纸或实测资料。

## 实施和验收

### 阶段一 操作原型

交付浏览器界面、项目空间、资料读取、字段核对、证据检索、按章生成接口、Word 草稿和部署配置。用虚构资料验证从上传到下载的操作。没有模型密钥时只验证离线链路，不能宣称模型端到端验收。

### 阶段二 业务闭环

选定同一报告类型的若干历史项目，由业务人员审定章节结构、必填项、26 张表的固定结构与文风。完成 OCR、图纸页渲染、设备/物料等实体提取、建议采纳对照、规范库和工程计算工具。用真实项目验证每个事实和表格的来源及准确性。

### 阶段三 版式与附件

建立可复用的公司 Word 模板，处理多分节、宽表横向页面、自动编号、页眉页脚、目录和图表交叉引用。图纸保留来源与审定版本。导出 PDF 并逐页比较，确认无截断、错页、缺字或附件错配。当前环境未安装工作区文档渲染运行时，原型导出尚未经过此项验收。

### 阶段四 企业部署

接入企业身份认证、项目成员权限、审计、数据备份、并发队列和可恢复任务。完成服务器迁移演练、供应商断连、模型异常、超大文件、文件格式错误、冲突资料和重复生成等测试。

## 待业务确认

公司拟优先服务的行业和报告类型、不同地区模板差异、现有输入材料完整度、必须人工签认的结论、文风与排版规范、数据能否出内网、并发人数和权限分工、模型和地图预算、是否需要 PDF 与 CAD 原图合订。模型选型目前未定，系统不锁定供应商。
