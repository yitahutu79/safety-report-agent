# 项目实施与验收控制（工作稿）

版本：0.1  
适用系统：安全设施设计报告辅助编制工作台  
状态：待双方确认目标平台、样本资料、验收指标和签署人员

## 1. 实施流程与阶段闸门

| 阶段 | 主要工作 | 进入下一阶段的确认材料 | 责任建议 |
| --- | --- | --- | --- |
| 需求与数据确认 | 锁定一期场景、部署平台、用户角色、接口边界；登记代表性项目资料、脱敏/授权状态、文件版本及基准答案 | 双方签字确认的需求基线、数据集登记表、验收测试方案 | 双方项目负责人；甲方业务与信息化人员 |
| 基础软件与环境 | 建立可重复安装的运行环境，确认模型服务、网络、磁盘、权限、备份与依赖版本 | 环境检查记录、安装包版本/哈希、部署记录 | 乙方研发/运维；甲方信息化人员 |
| 算法研发 | 实施解析、结构化提取、知识检索、Agent 工作流、内容校验及追溯 | 算法/提示词/Skill 版本记录，样本级中间结果及问题清单 | 乙方算法与安全专业人员 |
| 系统集成 | 接通资料、知识库、分析台账、章节生成、图件、Word 导出和权限边界 | 集成检查记录、功能版本及配置快照 | 乙方软件研发 |
| 测试验证 | 依照已确认数据集与预期结果执行功能、准确性、异常、性能和安全测试；记录原始结果与偏差 | 双方签认的测试记录、缺陷及回归记录 | 双方测试代表 |
| 成果交付 | 提交可运行版本、源代码/依赖清单（按合同约定）、说明文件、测试证据、部署与恢复资料 | 交付物清单、版本哈希、交接签收记录 | 双方项目负责人 |
| 现场演示与验收 | 使用双方确认的样本和验收脚本复现流程，核对通过条件及遗留项 | 现场演示记录、验收结论、遗留问题和整改期限 | 双方验收代表 |

## 2. 变更管理

需求、数据集、模型版本、提示词/Skill、检索参数、系统依赖和验收口径发生变化时，应记录变更编号、原因、影响范围、批准人及回归结果。任何测试结论都应关联明确的软件版本、配置快照、数据集版本和执行日期。

## 3. 待双方确认事项

- 甲方实际验收/生产平台：Windows、macOS、Linux 或多平台；CPU/内存/磁盘及是否可使用 GPU。
- 模型部署方式、可访问的模型服务、数据出境限制、密钥保管及模型调用预算。
- 代表性测试项目、文件清单、脱敏与使用授权、基准答案和专业复核人。
- 每项指标的目标阈值、抽样方法、失败判定和允许的人工介入边界。
- 并发用户数、任务量、响应时间、备份恢复目标及部署网络边界。
- 交付源代码、安装包、操作说明、培训、现场演示及缺陷整改的合同边界。

以上内容未确认前，不将开发机上的功能检查等同于甲方验收通过，也不声明抽取准确率、报告完整性或计算一致性达到特定数值。
